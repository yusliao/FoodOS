# FoodOS 客户演示与 P0 验收剧本

日期：2026-09-26。

本剧本用于展示“运营方工作台 + 饭店客户门户 + 外部 WMS 边界”的完整业务脉络。WMS 是实物库存、质检和仓内执行唯一权威；FoodOS 管客户、商品价格、采购与销售交易、客户服务和配送。演示环境中的参考 WMS 只验证标准契约、幂等通知和反馈纠偏，不代表客户真实仓库已经联调。

## 1. 演示环境

在 `src/FoodOS/deploy/docker` 执行：

```powershell
.\Start-FoodOsDemo.ps1
```

入口：

- 运营工作台：http://localhost:19081
- 饭店门户：http://localhost:19082
- API 健康检查：http://localhost:19080/health/ready
- 参考 WMS 状态：http://localhost:19083/demo/status

两端登录页均提供演示账号选择器，演示账号统一密码为 `Password123!`。运营端可选择超级管理员、经理、客服、采购、质检只读、仓储只读、拣货只读、调度、司机和财务岗位；饭店端可选择 Acme 与 Globex 的客户用户。

环境默认只监听 `127.0.0.1`。客户远程自助访问必须另行配置受控主机、HTTPS、访问控制和正确的外部 URL；不得公开参考 WMS 控制端口。

## 2. 演示前检查

```powershell
.\Test-FoodOsDemo.ps1
.\Set-FoodOsDemoWmsMode.ps1 -Mode accepted
```

检查结果必须确认 API、两端页面与参考 WMS 健康，`demoMode` 已开启，完整具名岗位、WMS 映射及参考 WMS 初始可售快照已经装载。该快照只为本地演示提供可下单数量，不代表真实库存，也不写 FoodOS 本地预占。演示期间不要进入旧质检放行、库存调整、上架、组波或拣货执行入口；这些动作由真实 WMS 负责。

## 3. 主线 A：运营方建立交易基础

1. 使用 `superadmin@root.com` 进入 admin，说明 root 是运营方身份域，饭店客户不能切换到该身份域。
2. 查看客户与门店，确认 Harbor Bistro/Acme 和 Campus Dining/Globex 分属不同客户，门店关联运营仓库。
3. 查看商品、品牌、分类、基础目录价、客户协议价和报价解析，说明同一商品可以按客户得到不同价格。
4. 查看订单中心、售后、报表和审计入口，说明运营方处理跨客户业务，但权限仍按岗位拆分。

验收重点：运营页面不要求伪造客户请求头；无权限岗位直输 URL 仍被拒绝。

## 4. 主线 B：饭店订货与平台承诺

1. 使用 Acme 饭店账号进入 dashboard，选择授权门店并打开订货目录。
2. 将有客户协议价的商品加入购物车并提交订单。
3. 立即打开订单详情，说明 FoodOS 已形成交易承诺；仓库确认状态与交易状态分离。
4. 返回 admin 订单中心，确认运营方可以看到该订单和客户、门店归属。
5. 使用 Globex 饭店账号验证看不到 Acme 的门店、价格、购物车和订单。

验收重点：下单不同步等待 WMS，也不在 FoodOS 写本地实物库存预占；相同提交幂等键不会产生两张订单。

## 5. 主线 C：仓库确认、断连和短配纠偏

参考 WMS 支持四种演示模式：

- `accepted`：接收出库通知，并回传 `outbound.allocated`。
- `pending`：返回暂时不可用，FoodOS 保持“待仓库确认”并后台重试。
- `rejected`：明确拒绝通知，FoodOS 显示仓库异常。
- `shortage`：先接单，再回传 `outbound.shortage`，订单行显示短配并进入仓库异常。

断连恢复演示：

```powershell
.\Set-FoodOsDemoWmsMode.ps1 -Mode pending
# 在饭店门户提交一张新订单，观察“待仓库确认”
.\Set-FoodOsDemoWmsMode.ps1 -Mode accepted
# 后台按同一幂等键重试，刷新订单详情后观察“仓库已确认”
```

短配演示：

```powershell
.\Set-FoodOsDemoWmsMode.ps1 -Mode shortage
# 提交另一张订单，等待参考 WMS 回传后刷新详情
.\Set-FoodOsDemoWmsMode.ps1 -Mode accepted
```

验收重点：模拟反馈只改变仓库确认和短配信息，不生成 FoodOS 本地批次分配、波次、拣货或库存扣减；重复事件由 Inbox 幂等处理，旧序列不能覆盖新事实。

## 6. 主线 D：采购、服务与岗位分权

1. 采购员进入采购单页面，读取实际供应商、仓库和商品并创建采购草稿。
2. 说明“FoodOS 已发送”和“WMS 已接单/已收货/已质检”是不同事实；真实入库、质检和可售库存仍等待客户 WMS 联调。
3. 客服进入工单与聊天，演示评论、状态处理、私有附件、频道消息和实时刷新。
4. 财务进入订单和现有对账入口，并确认看不到采购写入口。
5. 质检、仓储和拣货演示账号仅查看外部结果，不出现本地仓内执行按钮。

验收重点：岗位权限决定导航、按钮、请求和直接 URL；前端隐藏不能替代服务端授权。

以上范围不能用参考 WMS、Mock 浏览器测试或本地演示数据替代验收。

## 8. 演示结束

保留演示数据停止：

```powershell
.\Stop-FoodOsDemo.ps1
```

只有明确需要清空演示环境时才执行：

```powershell
.\Stop-FoodOsDemo.ps1 -RemoveData
```
